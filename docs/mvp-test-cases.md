## 1. 执行方式与判定

### 1.1 优先级和结果

| 标记 | 含义 |
|---|---|
| P0 | 关键主流程、身份隔离、丢数据、旧轮污染和取消失败；当前 MVP 的阻断项 |
| P1 | 异常恢复、兼容、交互和边界；失败需记录影响与处置，不得静默略过 |
| P2 | 较低频兼容或体验探索 |
| 扩展 | 第 12 步候选测试，本次只编写，执行需另行安排 |
| 后置 | 最终自研硬件测试；不作为替代载体的通过条件 |

结果使用：未执行 / 通过 / 失败 / 阻塞 / 不适用。没有设备、没有故障注入工具、无法取得证据，应标“阻塞”；不能标“通过”。不适用必须写明原因及适用平台。

用例里的“预期”是验收判据，不代表现有实现已满足。与现状不符时记录缺陷；例如错误重连、迟到音频、播放提前确认，都不能因为当前代码如此实现就修改判据。

### 1.2 三类环境

| 环境 | 布置 | 能证明什么 |
|---|---|---|
| T1：隔离逻辑环境 | 独立临时数据、假 ASR/LLM/TTS、受控 HTTP/WS 客户端 | 错误分支、鉴权、并发、取消、消息顺序 |
| T2：本机声学环境 | 一台 Mac/Linux 运行后端与载体进程，真实麦克风/扬声器 | 真实采放和本机端到端链路；不证明跨机器部署、开机自启 |
| T3：独立部署环境 | 服务器 S 与载体 C 分开；管理电脑 M 可关闭；H5 是独立客户端 | 载体脱离开发工具运行、跨网恢复、服务管理和长期使用 |

T3 中关闭的是管理电脑 M，不能关闭正在充当载体的 C 或服务端 S 后仍要求交流成功。如果使用同一台电脑同时承担三种角色，只能记为 T2。

Linux 和 macOS 各自记录结果。macOS LaunchAgent 的“用户登录后启动”与 Linux systemd 的“无人登录开机启动”分别验证，不混为一种能力。

所有账号、底座、记忆和录音使用虚构数据，设置独立 `LINGOU_DATA_DIR`。故障注入只能作用于测试进程、专用网络或测试目录。记录当前源码提交及未提交改动快照；不要只填 `main`。

### 1.4 共用操作和证据

- **H5 基线**：以 A 登录，BASE-A 已认领，FIG-A 已激活，无其他语音连接。
- **设备基线**：载体使用 DEV-A，`/api/asr/device-stream`，子协议 `lingou.device.voice.v1`，已收到有效的服务端 `status`，默认输入输出设备可用。
- **接口证据**：脱敏请求和响应、HTTP 状态码、调用时间、资源 ID；不导出 Bearer、设备 secret、原始二维码 token。
- **轮次证据**：`base_id`、`figure_id`、`session_id`、`turn_id`、`audio_id`、WS 关闭码、服务端 `turn_metrics` 与对应日志数量。
- **音频证据**：在许可的测试环境录制实际扬声器输出或使用回采，记录首声、末声、打断后是否仍发声。只看到 `write()` 返回或播放回执，不足以证明硬件已播完。
- **资源证据**：PID、子任务、文件描述符/线程数、麦克风占用、RSS、CPU、重连次数；测试前后各一份。
- **清理**：退出测试会话，停止本用例创建的服务/代理，撤销测试网络故障，释放音频设备；销毁临时数据前保存脱敏证据。

模型回复按语义判定，不要求字面等于示例。人设抽样重复 3 次并保留每次输出；必须匹配的只有测试协议、ID、数值边界及明确结构。

“10 次”“观察 30 秒”“运行 30 分钟”等是本用例的样本条件，不是已承诺 SLA。正式延迟/成本阈值留给扩展用例；本次不虚构 P95 或达标结论。

### 1.5 故障注入准备

| 编号 | 注入方式 | 适用场景 |
|---|---|---|
| FI-HTTP | 隔离代理延迟/丢弃某次响应；服务端是否已提交要单独记录 | 重试、断网、创建幂等、保存失败 |
| FI-WS | 受控 WS 服务/代理逐帧发送、暂停、断开，保存事件顺序 | 迟到、重复、乱序、缺帧、慢消费 |
| FI-PROVIDER | 假 provider 返回超时、空音频、非法音频、429/5xx | ASR/LLM/TTS 失败，不消耗真实费用 |
| FI-NET | 仅断开测试载体网络或停止测试服务，随后恢复 | 网络与服务恢复 |
| FI-STORE | 临时目录拒写、测试进程定点退出；备份后再执行 | 存储错误和事务恢复 |

以上是执行所需能力，不表示本仓库已有完整故障代理。缺少 FI-WS/FI-STORE 时相关用例标阻塞，不能用正常路径替代。浏览器 DevTools 的 Offline 只作用于浏览器，不能拿它模拟独立 Python 载体断网。

### 1.6 两个容易误判的边界

1. **取消与持久化**：取消发生在提交前，不应新增完成日志或记忆；若轮次已提交后才按停止，已有日志不应被要求倒删。两种情况都要验证取消之后没有新增的迟到提交、重复日志或声音。测试必须记录提交边界。
2. **记忆删除与近期历史**：删除确认事实后，它不得继续作为确认记忆进入 prompt，且候选不能自动复活。最近 6 轮历史中可能仍包含原句；判断“删除后不再回忆”需清理隔离夹具历史或让旧轮自然离开窗口，再问中性问题。

## 2. 端到端主场景

### E2E-01 [P0] 新账号首次创建并交流

- 前置：T2/T3；新用户 A；BASE-FREE；浏览器无草稿。
- 步骤：1）注册登录；2）扫码或粘贴 BASE-FREE 认领码；3）填写 FIG-A 的名字和一句话；4）只提交一次；5）在自动进入的交流页说“你好”。
- 预期：顺序为绑定→最少字段创建→交流；底座只激活一个角色；真实听到与设定一致的回答；成功轮次有完整 ID 和一条日志。
- 证据：全流程录屏、创建请求数量、底座/角色回读、实际发声和轮次日志。

### E2E-02 [P0] 关闭后返回当前角色

- 前置：A 已有两条确认记忆和至少 2 个完整对话轮次。
- 步骤：1）关闭 H5 与载体；2）重新打开同一浏览器；3）进入首页与交流页；4）问 Q1；5）使用新浏览器登录同一 A 再检查。
- 预期：恢复 FIG-A、确认记忆和最近对话；无需再次认领或新建；本地引导标记缺失也不会丢服务端资料；回答使用 A 的蓝色事实。
- 证据：前后资源 ID、首页/历史截图及回答；若非隔日执行，注明“关闭重开模拟”，不称为次日实测。

### E2E-03 [P0] 独立载体脱离管理电脑

- 前置：T3；S、C、M 职责明确；C 配好音频和 DEV-A。
- 步骤：1）在 C 启动服务；2）关闭所有 H5 通话；3）断开 SSH、退出 IDE并关闭 M；4）在 C 前由真人问 Q1；5）恢复管理连接查看日志。
- 预期：C 仍实际采音发声、使用 FIG-A 和 A 的记忆；只持久化本轮一次；没有依赖 M 的隧道、串口桥或 localhost 服务。
- 证据：部署拓扑、M 关闭时间、C 的实际声音、C/S 的轮次日志。

### E2E-04 [P0] H5 更正记忆后载体立即使用

- 前置：设备基线；A 已确认“喜欢蓝色”。
- 步骤：1）在 H5 将该事实改为“喜欢绿色”；2）刷新确认保存；3）等待旧问答退出近期窗口或使用无旧历史夹具；4）C 问 Q1；5）B 单独询问颜色。
- 预期：A 回答绿色；B 仍回答橙色；没有复制角色、重新配对或新增第二条冲突事实。
- 证据：修改前后同一个 memory_id、A/B prompt 中确认事实、两端回答。

### E2E-05 [P0] 对话—打断—故障恢复综合路径

- 前置：T3 设备基线，能记录扬声器声音与 WS。
- 步骤：1）问 Q2；2）声音开始后按回车/发送 SIGUSR1；3）说 Q3；4）结束后断开 C 网络 30 秒；5）恢复网络，再问 Q1。
- 预期：Q2 被停止；Q3 无 Q2 尾句污染；断网有本地反馈；恢复后新的会话能回答；断网期间旧内容不补播。
- 证据：连续录音、三个轮次 ID、取消/断开/恢复的时序、日志增量。

### E2E-06 [P1] 完整体验后检查普通路径

- 前置：已完成 E2E-01，默认开发与养成开关关闭。
- 步骤：1）依次浏览首页、交流、档案、记忆和设备设置；2）编辑基本人设/声线后继续交流；3）返回首页；4）尝试旧模拟器 URL。
- 预期：始终只有一个当前角色入口；正常路径无多角色切换、脑模式、关系快进、克隆和触摸台词编辑；旧 URL 不暴露工具。
- 证据：各页面截图、路由跳转、角色 ID 一致性。

## 3. 账号与身份

### AUTH-01 [P0] 注册、两种登录名与刷新

- 前置：T1/T2 新账号，无重名数据。
- 步骤：1）用用户名、合法邮箱和密码注册；2）用户名登录；3）刷新并调用 `/auth/verify`；4）退出后用同邮箱登录。
- 预期：同一 user_id；数据归属不变；刷新不创建新身份；用户响应不含密码或哈希。
- 证据：脱敏登录/verify 响应、用户记录数量。

### AUTH-02 [P1] 注册输入边界和重复

- 前置：T1，每组输入使用独立夹具。
- 步骤：1）用户名分别输入空白、1、50、51 字符；2）密码输入 7/8 字符与 72/73 UTF-8 字节，含中文；3）邮箱非法；4）两并发请求注册同一用户名/邮箱。
- 预期：合法边界可接受；非法输入有校验反馈且不写用户；并发最多创建一个身份；字节限制不能误按中文字符数处理。
- 证据：逐组输入描述、HTTP 结果和用户数量，不记录真实密码。

### AUTH-03 [P0] 错误、过期和伪造身份

- 前置：T1 已有 A；签发短期测试 token 或控制测试时钟。
- 步骤：1）错误密码登录；2）无 token、过期 token、被篡改 token 分别请求私有资源；3）使用设备凭据访问 `/figures`；4）观察 provider 调用计数。
- 预期：未授权 HTTP 返回 401；密码错误不暴露账号是否存在；设备身份不能冒充用户；拒绝在付费调用和私有数据读取之前发生。
- 证据：响应、provider 计数为 0、无资源写入。

### AUTH-04 [P0] A/B 连续换号与本地残留

- 前置：A/B 有不同角色、记忆、历史，A 有未完成草稿。
- 步骤：1）A 登录看完各页面并退出；2）同浏览器 B 登录；3）点击后退、刷新及打开记忆/历史；4）切回 A 查看草稿。
- 预期：B 不能看到 A 的缓存资料或草稿；A 的草稿按 A 的 user_id 恢复；旧请求迟到不能把 A 的内容写进 B 页面。
- 证据：网络响应身份、localStorage key（值脱敏）、页面快照。

### AUTH-05 [P0] H5 语音票据期限与重放

- 前置：T1；A 拥有 BASE-A；获取 `/auth/ws-ticket`。
- 步骤：1）票据首次连接正确底座；2）重用同票据；3）新票据连接其他底座；4）等待超过 60 秒后用另一票据；5）把访问 token 放 query/subprotocol 冒充票据。
- 预期：首次有效；重放关闭 4409；底座不匹配 4403；过期/错误身份 4401；拒绝时无 ASR/LLM/TTS 调用。
- 证据：每次握手与关闭码、签发/使用时间、provider 计数。

### AUTH-06 [P1] 退出清理与撤销语义

- 前置：A 在 H5 通话；保留一份仅测试用旧 token。
- 步骤：1）点击退出；2）检查麦克风、播放器、WS 和本地 token；3）后退进入私有页；4）从独立测试 HTTP 客户端再试旧 token。
- 预期：本地资源释放、私有页要求登录；记录旧 token 是否仍在有效期。当前退出是客户端清理，不能据此宣称服务端 JWT 已撤销；如要求立即撤销，单独登记产品/实现差距。
- 证据：资源状态、退出前后 storage、旧 token 请求结果。

## 4. 配对、激活与归属

### PAIR-01 [P0] 二维码与粘贴两条真实认领路径

- 前置：两个独立新夹具，各有未认领底座。
- 步骤：1）第一组允许摄像头扫码；2）第二组拒绝摄像头后粘贴完整认领 URL；3）刷新设备列表；4）检查预置时设备凭据与二维码。
- 预期：两路径都认领真实底座到当前 owner；拒绝摄像头可回退；二维码只携带认领 token，不包含设备语音 secret。
- 证据：底座 owner 回读、摄像头权限路径、脱敏二维码结构。

### PAIR-02 [P1] 损坏、伪造和格式错误认领码

- 前置：T1/T2，BASE-FREE 未认领。
- 步骤：1）空字符串、普通网址、截断 token 分别认领；2）修改 base_id 或 secret；3）尝试包含路径分隔符的 ID；4）再使用原合法码。
- 预期：非法输入拒绝且不创建/认领底座；报错不泄漏有效 secret；合法码仍可正常认领。
- 证据：错误响应和前后底座数量、归属。

### PAIR-03 [P0] 重复扫码和并发认领同一底座

- 前置：T1，A/B 同时持有同一测试认领码。
- 步骤：1）A/B 并发提交；2）确定成功者；3）成功者再扫 3 次；4）失败者再次扫。
- 预期：仅一个 owner；成功者重试幂等；另一方收到占用冲突 409；不能出现两边都成功或偷偷转移归属。
- 证据：并发响应、底座单一 owner、无重复底座记录。

### PAIR-04 [P1] 一个账号认领第二底座

- 前置：A 已绑定 BASE-A，BASE-FREE 未绑定。
- 步骤：1）A 尝试认领 BASE-FREE；2）刷新列表；3）A 解绑 BASE-A；4）再次认领 BASE-FREE。
- 预期：未解绑时返回账号已有底座冲突；原 BASE-A 不受影响；解绑后允许新绑定。
- 证据：409 响应、两底座绑定前后状态。

### PAIR-05 [P0] 解绑持久化及设备失权

- 前置：设备基线，有已保存角色/记忆。
- 步骤：1）关闭设备会话后 H5 解绑；2）重启后端；3）刷新 A 的角色和底座；4）旧 DEV-A 再连设备 WS 和发事件。
- 预期：解绑不因重启反弹；角色、记忆保留；底座无 owner/激活关系；旧凭据在未认领状态不能工作。
- 证据：重启前后绑定记录、角色/记忆回读、WS/事件拒绝结果。

### PAIR-06 [P0] 非归属角色不能激活

- 前置：T1；A/B 分属 BASE-A/FIG-A 与 BASE-B/FIG-B。

- 前置：H5 编辑页，有至少两个可用候选声线。
- 步骤：1）试听 S1；2）选择并试听 S2；3）保存、刷新；4）新开一轮语音。
- 预期：点击选择与实际试听对象一致；保存后回读 S2；后续对话请求使用 S2；声音由用户终端输出。
- 证据：preview speaker 请求/响应头、保存回读、实际音频。

### OUTPUT-02 [P1] 快速切换试听与离开页面

- 前置：FI-HTTP 可延迟 S1 音频。
- 步骤：1）请求 S1 后立即请求 S2；2）先返回 S2 再返回 S1；3）播放中离开页面；4）返回重新试听。
- 预期：只播放当前请求代次；迟到 S1 不抢占 S2；离开时释放播放器/对象 URL；返回可正常试听。
- 证据：请求时序、声音、播放器状态。

### OUTPUT-03 [P0] TTS 空内容或解码失败

- 前置：T1，FI-PROVIDER 分别返回空字节、损坏音频、错误格式。
- 步骤：1）分别调用试听和通话；2）检查错误反馈；3）恢复合法音频再执行。
- 预期：试听返回明确音频不可用错误；通话不能记为音频播放成功；不调用后端机器本地扬声器回退；恢复后可重试。
- 证据：错误码、playback_failed/audio_failed、服务端无本地播放、恢复音频。

### OUTPUT-04 [P0] 播放完成回执与实际末声一致

- 前置：T2；固定包含清楚尾音“播放结束”的长音频，记录实际扬声器输出。
- 步骤：1）分别用 H5 与载体播放；2）捕获最后一帧到达、write 返回、回执和尾音时间；3）收到 completed 后立即停止客户端。
- 预期：不能只因字节传完/write 返回就提前认定已播完；末尾完整，不被停止动作截断；测量需注明录音与进程时间的同步误差。
- 证据：尾音录音、回执时间、音频总时长和停止时刻。此项必须实测，不能用 FakeAudio 通过代替。

### OUTPUT-05 [P0] 播放失败和回执超时

- 前置：T1，合法音频已发送；FI-WS 可不回执或返回失败。
- 步骤：1）不发送 completed 并等待服务器当前 30 秒播放等待窗口；2）另组主动发 playback_failed；3）再起正常轮。
- 预期：未确认/失败轮不得标 completed；能看到 audio_failed/超时信息；资源释放后下一轮可工作。
- 证据：turn_metrics、超时起点/结束点、下一轮结果。

### OUTPUT-06 [P1] 系统静音、音量和错误输出设备

- 前置：T2，可切换内置扬声器、耳机或 USB 声卡。
- 步骤：1）静音系统后发起对话；2）解除静音；3）切到另一输出设备；4）显式选择输出设备再对话。
- 预期：系统静音可能仍产生软件回执，报告不得称“用户实际听到”；正确路由时仅目标设备发声；错误路由可诊断而非误报 provider 故障。
- 证据：系统输出/音量设置、实际听测与软件回执分开记录。

## 10. 设备身份与凭据生命周期

### DEVAUTH-01 [P0] 设备身份确定 owner/base

- 预期：实际资源只能由 DEV-A 推导；客户端参数不能越权选择 B；回复和日志属于 A。

### DEVAUTH-02 [P0] 缺失、错误类型及无语音权限

- 前置：T1，准备缺失 secret、篡改 secret、用户 Bearer、仅 events:write 的设备凭据。
- 步骤：1）逐组连接设备 WS；2）观察应用关闭码；3）统计 provider 调用。
- 预期：关闭 4401，无付费调用、无业务会话；不能使用用户票据冒充设备凭据。
- 证据：每组关闭码、provider 计数、无新增日志。

### DEVAUTH-03 [P0] 未认领或未激活的设备

- 前置：一组未认领；另一组已认领但无当前角色。
- 步骤：1）两组分别连接；2）按真实流程认领/激活；3）用同一对应凭据重试。
- 预期：未认领身份被拒；有 owner 但未激活关闭 4404；不启动识别计费；激活后正常。
- 证据：两种失败和恢复结果、激活前 provider 计数。

### DEVAUTH-04 [P0] 轮换后旧密钥不可复用

- 前置：已预置并认领的生产类型测试凭据，关闭现有会话。
- 步骤：1）在隔离数据目录运行轮换；2）旧 DEV-A 分别访问事件/语音；3）更新 C 配置为新凭据；4）重启载体。
- 预期：旧凭据全部失效，新凭据正常；owner 和当前角色不变；新 secret 只返回一次且不写入日志/仓库。
- 证据：旧新访问结果、资源 ID、脱敏配置权限。

### DEVAUTH-05 [P0] 活动连接期间解绑、撤销或转移

- 前置：T1/T3，设备已连接并可提问，分别使用独立夹具。
- 步骤：1）聆听中解绑；2）另组生成中撤销凭据；3）另组轮换密钥或解绑后 B 认领；4）旧连接继续发 PCM；5）再尝试重连。
- 预期：旧连接不能继续读取 A/B 私有资料或以旧身份写新轮次；未完成输出应停止；重连拒绝旧权限。即时失权若未实现，记录 P0 风险，不能只凭“新握手被拒”判整项通过。
- 证据：变更时刻、存量 WS 行为、之后 provider/日志调用和 owner。

### DEVAUTH-06 [P0] 设备凭据不能调用用户接口

- 前置：T1，DEV-A 有全部合法设备域权限。
- 步骤：1）Device header 调 `/figures`、`/sync`、记忆 CRUD；2）把凭据放 Bearer；3）尝试其他账号音频资源。
- 预期：用户域鉴权拒绝；不返回角色列表、记忆、音频；不因设备归属 A 就授予 A 的用户 API 权限。
- 证据：各入口状态码、响应正文和无写入。

### DEVAUTH-07 [P1] 错误/缺失子协议与多余字段

- 前置：T1 受控 WS 客户端。
- 步骤：1）不发子协议；2）发浏览器子协议；3）发未知版本；4）正确子协议后发送未知 JSON 消息和伪造 owner 字段。
- 预期：握手版本错误拒绝；未知消息不授予权限或改变归属；不能因额外字段触发未授权 API。
- 证据：协商结果、关闭码、资源前后状态。

### DEVAUTH-08 [P1] 生产与测试凭据隔离

- 前置：隔离后端使用生产默认开关，准备测试凭据。
- 步骤：1）默认配置连接测试凭据；2）请求测试底座/测试凭据接口；3）仅在另一个隔离服务显式开启测试开关，再重复；4）检查 secret 输出。
- 预期：默认测试入口不可用；测试凭据不能用于生产默认环境；开发开关只影响隔离测试服务；明文 secret 不进入版本库和普通日志。
- 证据：两套非敏感配置、访问结果、日志脱敏检查。

- 预期：不挂死或无限占用线程；出错不回传假播放完成；能自动或明确手动重启恢复；记录是否需要重启客户端，不能承诺未经验证的热插拔。

- 步骤：1）问 Q2；2）观察回复期间麦克风上行；3）播放结束后保持静默 15 秒；4）再说 Q3。

- 预期：进程与键盘读取任务均能退出；无未关闭麦克风/输出流/WS；部分启动失败也释放资源；下一次启动无“设备忙”残留。

## 12. 打断、迟到与连接仲裁

- 预期：已取消的音频 ID 不继续播放；未配对描述符/帧不污染新轮；必要的失败回执绑定原 ID。

### CANCEL-05 [P0] 旧 stop_audio 晚于新轮开始

### CANCEL-06 [P0] H5 接管替代载体

### CANCEL-07 [P0] 载体接管 H5、两个载体竞争

- 预期：最新合法 BASE-A 连接唯一有效；旧端停下且不自动争抢；BASE-B 不被误踢或串音。

### CANCEL-08 [P1] 已提交轮次的末尾停止

- 前置：T1/T2，能够观察日志提交时点与播放尾部。
- 步骤：1）确认某轮已经提交；2）尾音处触发停止；3）查旧日志与候选；4）再发新轮。

- 证据：提交/取消先后、日志唯一性、尾音、下一轮状态。

## 13. 网络、服务与错误恢复

### RECOVER-04 [P0] 后端重启与角色记忆保持

- 前置：T3，A/B 数据保存在专用持久测试目录。
- 步骤：1）记录当前角色和确认事实；2）停止 S 的测试服务；3）重启同数据目录；4）载体自动恢复；5）H5 刷新并问 Q1。
- 预期：新 WS 会话，底座/角色/记忆不丢；不重新创建身份；只恢复后端服务即可继续。
- 证据：重启前后 ID/记忆、会话变化、对话结果。

### RECOVER-05 [P1] DNS、地址与 TLS 失败

- 前置：专用测试域名和证书；不得跳过生产证书校验。
- 步骤：1）不存在主机/错误端口；2）WSS 过期证书/主机名不匹配；3）恢复有效服务地址；4）重启或重连。
- 预期：错误明确且不泄露 secret；无关闭 TLS 校验的静默降级；恢复有效配置后可连；不在日志打印带凭据 URL。
- 证据：异常类型、脱敏地址、TLS 校验结果、重试次数。

### RECOVER-06 [P1] ASR、LLM、TTS 分别不可用

- 前置：T1，FI-PROVIDER 一次只注入一类故障。
- 步骤：1）ASR 超时/鉴权失败；2）LLM 429/超时；3）TTS 空音频/5xx；4）每组恢复正常 provider，再执行一轮。
- 预期：错误按阶段可定位；无音频不报完成；不留下永久 speaking 或麦克风静音；恢复可对话；失败消耗与成功轮分开记录。
- 证据：阶段错误、调用计数、客户端状态和恢复结果。

### RECOVER-07 [P1] 慢链路、抖动与积压

- 前置：T1/T3 专用代理；设置额外延迟 200/1000/3000 ms，限制带宽并记录条件。
- 步骤：1）短句交流；2）长回复；3）链路变慢时打断；4）恢复带宽并开始新轮。
- 预期：允许变慢，但不能内存无界增长、挂死或乱播；打断不被长队列永久阻塞；旧数据不在恢复时集中播放。
- 证据：各档网络参数、队列/内存、音频时序、超时或恢复行为。

### RECOVER-08 [P1] 恢复后健康状态与旧完成标记

- 前置：设备曾完成一轮，再通过 FI-NET 断开。
- 步骤：1）记录旧 final/reply/完成事件；2）连接新会话但不说话；3）健康检查读取状态；4）新说 Q3。
- 预期：新会话未完成前不能沿用旧 completed 结果报成功；健康检查区分已连、可采音、正在播放和本轮完成。
- 证据：两次 session 对应的健康状态、完成事件/时间和实际轮次。

## 14. PCM 与 WebSocket 消息边界

这些用例需 T1 的 FI-WS 逐帧控制，默认使用虚构音频；听测畸形音频前先限制输出音量。

### PROTOCOL-01 [P0] 标准多帧顺序与完整性

- 前置：固定 9,000 字节 PCM，单一 session/turn/audio。
- 步骤：1）发送 audio_output 和 4096/4096/808 字节帧描述符+二进制；2）比较接收/播放内容；3）检查回执。
- 预期：按 0/1/2 顺序，字节完整；decoded/started/completed 对应同一个 audio_id；最后一帧前不完成。
- 证据：字节摘要、顺序和回执；协议正确仍需 OUTPUT-04 判实际播放结束。

### PROTOCOL-02 [P0] 描述符与二进制不匹配

- 前置：FI-WS，分别创建新连接。
- 步骤：1）无描述符发二进制；2）描述符长于/短于实际帧；3）连续两个描述符再发帧；4）缺最后二进制后断开。
- 预期：非法组拒绝/失败且不作完整成功；不能把前一描述符套到下一轮二进制；清理后能建立正常新会话。
- 证据：每组错误、是否发声、完成回执数量和恢复结果。

### PROTOCOL-03 [P1] 格式、大小及奇数字节边界

- 前置：FI-WS，客户端音量最低或使用假输出。
- 步骤：1）空 PCM、奇数个字节；2）4096/4098 字节帧；3）声明 MP3/stereo/错误 sample_format；4）采样率 16000/48000 冒充设备下行。
- 预期：设备下行契约只接受 24 kHz mono s16le、每帧不超 4096；不支持格式不能当合法 PCM 发声或报成功；异常可诊断。
- 证据：逐项描述符、帧长度、错误和回执。

### PROTOCOL-04 [P0] 分帧索引重复、乱序与缺帧

- 前置：FI-WS，声明 chunk_count=3。
- 步骤：1）发送 0/2 缺 1；2）0/1/1/2 重复；3）1/0/2 乱序；4）index=-1/3、count=0；5）帧中途变 count。
- 预期：非法顺序不能拼成“成功播放”；重复帧不重复发声；不越界；只有完整有序的本段音频可完成。
- 证据：消息顺序、played 字节摘要、失败/成功回执。

### PROTOCOL-05 [P0] 旧 session/turn 的音频注入

- 前置：客户端新会话 B 已建立，保留旧会话 A 的消息夹具。
- 步骤：1）向 B 注入 A 的 descriptor+PCM；2）注入旧 session_id 的 status；3）发送 B 的正常帧。
- 预期：旧身份不能覆盖当前 session 或发声；B 的正常回执仍用 B 的 ID；不能仅把“最近收到的 ID”当可信当前状态。
- 证据：客户端当前 ID、实际播放内容、回执 ID。

### PROTOCOL-06 [P0] 回执伪造、重复与阶段乱序

- 前置：T1 服务端活动 turn，只有一个合法 audio_id。
- 步骤：1）发送其他 session/turn/audio 的 completed；2）重复合法 completed；3）completed 后再 failed；4）另组未 started 就 completed。
- 预期：跨身份回执不能完成当前轮；重复处理幂等；矛盾/乱序需拒绝或明确标异常，不制造“实际播放已证实”的指标。
- 证据：服务端状态迁移、metrics、是否错误唤醒 playback_done。

### PROTOCOL-07 [P1] 非法 JSON 和未知消息

- 前置：T1 FI-WS/受控设备客户端。
- 步骤：1）双向分别发截断 JSON、数组/null、未知 type；2）整数位置放字符串；3）发超出上限的消息；4）恢复合法消息。
- 预期：不崩溃整台服务、不修改他人会话；错误有界处理；未支持消息不授予权限；超大消息不能造成不受控内存增长。
- 证据：错误/关闭码、进程存活和资源、其他会话可用性。

### PROTOCOL-08 [P1] 同轮多段音频与慢输出

- 前置：同一 turn 两个 audio_id，假声卡写入可延迟；另用真实声卡验证。
- 步骤：1）先后发送两段；2）让第一段输出变慢；3）期间发送 stop_audio/错误；4）另一组正常播完。
- 预期：多段不交错、漏播；接收控制消息不能被整个长播放长期阻塞；每个 audio_id 单独回执，全部完成后才完成轮次。
- 证据：控制接收延迟、两段声音、各 audio_id 状态和 turn 状态。

## 15. 自动启动、权限和部署

### STARTUP-01 [P1] 模板语法与实际路径

### STARTUP-02 [P0] Linux 无登录冷启动

- 前置：T3 Linux 专用载体，安装已校验的 systemd 服务，音频设备权限配置好。
- 步骤：1）记录服务启用状态；2）重启 C；3）不登录桌面、不 SSH；4）真人直接提问；5）之后取服务日志。
- 预期：服务以目标普通用户启动，能打开真实声卡并交流；network-online/sound 的启动顺序不会令其永久失败。
- 证据：boot ID、单元 active 时间、真人音频、service 用户和轮次日志。

### STARTUP-03 [P1] macOS 登录启动与音频权限

- 前置：T3 macOS 测试用户，安装 LaunchAgent 并为实际运行程序配置麦克风权限。
- 步骤：1）注销再登录；2）不打开 Terminal/IDE；3）提问；4）检查 launchd 状态；5）重启后未登录与已登录分别观察。
- 预期：登录后自动工作；清楚记录 LaunchAgent 依赖登录，不能称“无人登录开机即运行”；隐私权限不会因启动方式改变失效。
- 证据：登录时间、launchd PID、权限、实际采放。

### STARTUP-04 [P1] 进程意外退出与人工停止

- 前置：已安装测试服务，记录准确 PID。
- 步骤：1）只终止本测试进程模拟崩溃；2）观察管理器重启；3）完成一轮；4）用 systemctl stop/launchctl bootout 显式停止；5）观察 30 秒。
- 预期：崩溃可恢复，旧录音不补传；显式停服务后不被错误拉起；无重复实例争用声卡/会话。
- 证据：旧新 PID、Restart 日志、声音、停止后的状态。

### STARTUP-05 [P0] 凭据文件权限与日志脱敏

- 前置：真实测试 secret 仅放 C 的环境文件，报告不保存其明文。
- 步骤：1）文件设置 owner-only；2）用服务用户启动；3）以其他普通用户尝试读取；4）检查日志、错误栈、进程参数、仓库和 CSV。
- 预期：服务能够读取配置；其他普通用户不能读；secret 不出现在命令行/报告/仓库。systemd 由管理器读取环境文件，macOS source 由登录用户读取，应分别检查。
- 证据：文件权限/属主、读取权限结果、脱敏扫描结论。

### STARTUP-06 [P1] 配置或音频依赖缺失后修复

- 前置：T1/T3，备份测试配置。
- 步骤：1）删除环境文件/遗漏 credential；2）另组缺 sounddevice/PortAudio；3）观察错误；4）恢复配置依赖；5）启动交流。
- 预期：失败原因明确，无无限重启刷日志/提示音；不会回退成匿名身份；修复后可启动，不要求重建角色。
- 证据：退出码、管理器重试频率、恢复步骤和轮次。

### EXT-04 [扩展] 用量与成本可追溯

- 前置：隔离 provider 项目或可区分测试 request_id，价格版本有日期。

- 步骤：1）完成可验证备份；2）在新目录/新环境重建依赖和服务；3）恢复；4）登录核对角色、绑定、记忆和日志；5）检查是否需要独立保管密钥。

- 证据：备份清单/校验值、恢复命令、前后数据比对及缺失项。

### EXT-06 [扩展] 长时间故障、磁盘满与升级回退

- 预期：失败有界、不损坏已有已提交数据、不无限消耗；恢复路径可执行；尚无升级/回退方案时只登记缺口。
- 证据：注入配置、错误与恢复时间、数据完整性比对。

### HW-01 [后置] 电气接线与启动版本确认

- 前置：最终硬件设计冻结并批准刷写；若仍使用 DNESP32S3 参考板，使用其已确认引脚表。
- 步骤：1）核对供电、电平和引脚；2）刷写指定版本；3）核对启动指示；4）采音/发声/触摸逐模块检查。
- 预期：按最终硬件合同通过；参考板要求红闪 3 次及 LED18/FSR16/Mic5/7/4；这些编号不强行套用新设计。
- 证据：板卡版本、接线图、固件 hash、实机照片/录屏。

### HW-02 [后置] 声学、底噪与回声消除

- 前置：最终麦克风、扬声器、功放、腔体样机；声学标准预先确认。
- 步骤：1）静音底噪；2）近/远场与不同朝向；3）背景噪声；4）播放中打断/AEC；5）最大约定音量。
- 预期：按标准评估拾音、回声、削波、啸叫和可懂度；替代载体半双工结果不能证明最终 AEC。
- 证据：环境噪声、距离、频响/录音、测量设备和结果。

### HW-03 [后置] 功耗、温升与续航

- 前置：最终电源、电池和外壳；批准测试条件。
- 步骤：1）待机、聆听、播放、网络重连分别测电流；2）连续工作测温；3）低电量/充电状态切换；4）验证关机恢复。
- 预期：满足硬件预设阈值；电池与温升异常按实验规程停止；不从电脑客户端 CPU 推算最终设备续航。
- 证据：电流/温度曲线、时长、电池规格和测量条件。

### HW-04 [后置] 配网、OTA、触摸和恢复出厂

- 前置：最终方案已实现并有设备身份/用户数据处置规则。
- 步骤：1）首次配网与错误密码；2）断电/断网中的 OTA；3）实体按钮/触摸与去抖；4）恢复出厂并重新认领。
- 预期：可恢复、不变砖；设备凭据与旧 owner 权限按规则处理；触摸不造成误取消或连续抢连；未实现能力不标通过。
- 证据：版本切换、网络/电源事件、认领状态及实物操作录像。
