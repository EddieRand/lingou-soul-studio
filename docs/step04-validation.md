## 设备预置与配对

设备交付前运行：

```bash
cd services/companion-server
.venv/bin/python -B -m scripts.provision_base \
  --base-id BASE-DEVICE-001 \
  --data-dir /absolute/path/to/runtime-data
```

命令生成两份独立随机凭据：

- `qr_payload`：印在底座二维码上，仅用于账号认领。
- `device_credential`：写入设备受保护配置，仅用于设备事件。

服务端只保存 SHA-256，不保存明文。明文只在预置命令输出一次。用户通过
`POST /api/bases/pair` 认领；一期每个账号只绑定一个底座。同一账号重复扫描幂等成功，
其他账号不能抢占。`POST /api/bases/{base_id}/unbind` 清除 owner、当前角色和角色反向关联，
但不删除灵偶档案。

## 创建与激活

普通创建请求携带：

- `creation_request_id`：浏览器 `sessionStorage` 中跨刷新保留，创建成功后删除。
- `activate_base_id`：当前服务端返回的已绑定底座，不使用硬编码 ID。

服务端按 `owner + creation_request_id` 去重。角色完整档案已包含在创建请求中，
前端不再创建后重复调用角色档案保存。新角色文件、旧角色解绑和底座当前角色通过
`data/.transactions/` redo journal 一次提交；写入中断后，下一次启动或重试先补齐事务。

## 设备事件

生产设备使用 `Authorization: Device <credential>`，正文包含：

```json
{
  "event_type": "light_touch",
  "event_id": "unique-event-id",
  "occurred_at": "2026-09-15T08:00:00+00:00"
}
```

服务端拒绝同一底座最近窗口内的重复 ID，以及服务器时间前后超过 5 分钟的事件。
解绑后因底座没有 owner，设备事件立即失效；重新绑定后恢复。用户可永久撤销设备凭据，
撤销后必须重新安全预置。
