# 嵌入式实时语音最佳实践实施路线

## 目标

本路线将火山引擎“实时对话式 AI 硬件”及
`rtc-aigc-embedded-demo` 中值得借鉴的能力拆成可独立实施、验证和回退的任务。
学习范围限定在设备声学、媒体传输、配网、安全、状态反馈和运行诊断，不以替换
LINGOU 已验证的身份、角色、记忆和对话核心为目标。

参考基线：

- 产品介绍：
  `https://github.com/volcengine/ai-app-lab/tree/main/demohouse/conversational_ai_embedded`
- 示例代码：
  `https://github.com/volcengine/rtc-aigc-embedded-demo`
- 本次分析使用的示例代码提交：
  `9ee3b3ba98169b9020d15d8a92d1127e51a75a06`（2025-09-09）
- 产品页中的低于 300 KB、80% 丢包和毫秒级检测属于上游产品描述，不直接算作
  LINGOU 验收证据；必须在目标硬件和目标网络上重新测量。

## 不可破坏的边界

以下能力继续由 LINGOU 服务端掌握，RTC 或设备 SDK 不得成为新的事实来源：

- owner、base、figure 的归属与设备撤权；
- persona 构建和 AI 身份规则；
- 已确认共同记忆、候选确认、纠正和删除墓碑；
- `session_id`、`turn_id`、`audio_id` 及取消后的迟到结果隔离；
- 客户端真实播放回执和轮次完成判定；
- H5 与设备的单底座最新连接仲裁。

实施约束：

1. 当前 `feat/mvp-step11-software` 只完成软件本地放行，不实现最终硬件能力。
2. 硬件任务从软件放行后的冻结点创建独立分支，例如
   `feat/hardware-voice-adapter`。
3. RTC 验证使用单独的实验分支，例如 `spike/rtc-lite-transport`，不得直接替换
   当前 WebSocket 路径。
4. 协议修改必须向后兼容 `lingou.device.voice.v1`；先写协议和合同测试，再改实现。
5. 任何方案都不得把 AK、SK、RTC AppKey、用户 Bearer 或明文长期密钥写入固件、
   URL、仓库和日志。

## 执行规则

- 同一时间只推进一项任务。
- 每项任务必须保存：设计说明、代码或配置、自动验证、真实环境证据、已知限制。
- 当前任务未达到退出条件，不开始依赖它的下一项。
- 失败的 PoC 保留结论和证据，不通过降低既有身份、记忆或播放语义来换取通过。
- 标记完成只表示该任务的验收条件满足，不代表最终硬件整体完成。

## 第一阶段：软件边界和可测基线

### EV-01 设备协议能力协商设计

**状态**：已完成。规范见
[`device-voice-protocol-v1.md`](device-voice-protocol-v1.md)，验收记录见
[`validation/ev01-protocol-design.md`](validation/ev01-protocol-design.md)。

**学习点**：上游可选择 PCM、G711A、Opus 等编码，设备和云侧先协商媒体能力。

**交付物**：

- 编写 `lingou.device.voice.v1` 的向后兼容扩展设计；
- 定义设备上报的 codec、采样率、声道、最大帧、双工和 AEC 能力；
- 定义服务端选择结果、拒绝原因及旧客户端默认值；
- 明确 RTC 只替换媒体层时，如何映射现有 session/turn/audio 事件。

**验收**：

- 旧客户端不发送 capabilities 时仍走当前 PCM 路径；
- 不允许设备自行声明 owner、figure 或服务端 session；
- 合同测试覆盖未知能力、降级、拒绝和重新连接；
- 本任务只形成协议和测试设计，不改对话、记忆或 persona。

### EV-02 延迟、声学和弱网基线工具

**状态**：已完成基线采集。证据见
[`validation/ev02-baseline-20260917/README.md`](validation/ev02-baseline-20260917/README.md)。
直接 provider 链路和修复后的 30 秒恢复通过；当前 Mac 声学回采不合格，作为
EV-05 的已知基线问题保留。

**学习点**：上游优势必须通过指标验证，不能以产品宣传或单次成功替代。

**交付物**：

- 复用当前 `turn_metrics`，统一记录端点判停、首字、首音频、播放开始/完成和打断；
- 增加独立载体侧连接、缓冲、播放欠载和重连记录；
- 建立隔离的延迟、抖动、限速、断开和恢复故障注入方案；
- 固定测试语料、距离、播放音量、网络档位和证据格式。

**验收**：

- 当前 WebSocket + PCM 路径先形成可重复基线；
- 30 秒离线内容不积压上传，恢复后使用新 session；
- 结果能区分传输、ASR、LLM、TTS、解码和实际播放耗时；
- 80% 丢包只作为压力探索项，未验证前不写成 LINGOU SLA。

## 第二阶段：目标硬件基础能力

以下任务必须在硬件到货后的独立适配分支执行。

### EV-03 板级 HAL 和任务模型

**状态**：进行中。独立分支、软件侧 HAL、固件侧接口、任务模型、假 HAL、生命周期
回滚和静态固件编译已完成；目标板未连接，真实 heap、PSRAM、任务栈和 CPU 数据待补。
见 [`hardware-hal.md`](hardware-hal.md) 和
[`validation/ev03-hal-20260917/README.md`](validation/ev03-hal-20260917/README.md)。

**学习点**：上游以统一 HAL 和音频流水线隔离具体芯片、板卡和业务。

**交付物**：

- 抽象麦克风、扬声器、LED、触摸/按键、网络、时钟和安全存储接口；
- 固定采音、播放、网络、控制和诊断任务的职责、优先级及队列边界；
- 将 DNESP32S3 引脚和驱动限制放入板级实现，不进入协议或业务层。

**验收**：

- 使用假 HAL 可运行协议合同测试；
- 更换板级实现不修改服务端对话、记忆和身份逻辑；
- 任务退出、设备重启和部分初始化失败均释放资源；
- 记录栈、堆、PSRAM 和 CPU 占用基线。

### EV-04 非阻塞音频流水线

**状态**：进行中。固件与主机载体实现、静态编译和自动回归已完成；无目标板，
真实 `stop_audio` 到扬声器静音时延及持续运行数据待补。见
[`validation/ev04-audio-pipeline-20260917/README.md`](validation/ev04-audio-pipeline-20260917/README.md)。

**学习点**：上游使用采集、算法、编码、网络、解码和播放流水线，避免网络回调直接
阻塞 I2S。

**交付物**：

- 采音以固定 20 ms 帧进入有界队列；
- 下行音频经过有界抖动缓冲后由独立播放任务写 I2S；
- 控制消息可抢占音频队列，取消时清除旧 turn 的全部缓冲；
- 增加欠载、溢出、丢帧和最大排队时长统计。

**验收**：

- 慢 I2S 写入不阻塞心跳、取消或断线处理；
- `stop_audio` 到设备停止输出满足预先约定的打断门槛；
- 不出现旧音频补播、无限队列或错误 completed 回执；
- 多帧顺序、边界和播放回执继续通过既有协议测试。

### EV-05 AEC、AGC 和噪声抑制

**学习点**：上游端侧音频 3A 是实现远场拾音和全双工的基础。

**交付物**：

- 选定 ESP-SR AFE、ESP-ADF algorithm stream 或经验证的等价实现；
- 把扬声器参考信号正确送入 AEC；
- 为 AGC、噪声抑制、麦克风增益和削波保护建立可版本化配置；
- 保留处理前后的受控录音和算法版本信息。

**验收**：

- 静默、近讲、远讲、背景噪声和设备播放场景分别留证；
- 设备播放不再稳定触发自问自答；
- 用户在设备播放时的语音仍可被识别；
- 目标距离、音量和环境下的指标阈值在执行前明确，不能仅凭主观听感通过。

### EV-06 VAD、端点检测和语音打断

**学习点**：上游使用 VAD、语义和持续说话时间实现无需按键的智能打断。

**交付物**：

- 将静音判停和打断持续时间参数化；
- 对 600/900/1200/1500 ms 等候选值做真人语料 A/B；
- 将语音打断映射到现有 `cancel_turn`，压力传感器继续作为兜底；
- 明确推测性 ASR 文本只能预热，不能提前提交日志或共同记忆。

**验收**：

- 自然停顿不会频繁截断句子；
- 背景人声和设备自身声音不会频繁误打断；
- 有效打断后旧生成、旧播放和迟到结果全部停止；
- 下一轮继续使用新的 turn，现有取消测试不退化。

### EV-07 Opus 和媒体能力降级

**学习点**：压缩编码可显著降低原始 PCM 带宽，为弱网和移动网络留出余量。

**交付物**：

- 增加可选 Opus 上下行或经验证的等价低码率编码；
- 保留当前 PCM 作为协议回退和诊断基线；
- 固定帧长、码率、复杂度、PLC/FEC 配置和解码失败行为；
- H5 与设备分别协商，不能因设备编码改变 H5 音频路径。

**验收**：

- 编码协商失败能安全回退或明确拒绝；
- 断线、取消和旧 turn 隔离在压缩路径上与 PCM 一致；
- 对比带宽、CPU、内存、音质和首音频延迟；
- 不以节省带宽为由取消播放回执或降低身份校验。

### EV-08 配网、设备身份和 TLS

**学习点**：借鉴上游 NVS + AP 配网流程，但修复开放 AP、明文日志和关闭证书校验等
demo 风险。

**交付物**：

- 设计首次配网、错误密码、换网、离线重试和恢复出厂状态机；
- SoftAP 或 BLE 配网必须结合二维码、一次性 PIN 或等价的实体持有证明；
- 启用安全启动、Flash/NVS 加密及服务端 CA 校验；
- 长期设备身份仅用于换取短期会话权限，支持轮换、撤销和 owner 解绑。

**验收**：

- 固件、串口、崩溃日志和配网页面均不泄露 Wi-Fi 密码或设备密钥；
- 错误证书、主机名不匹配和过期凭据必须拒绝，不能静默降级；
- 撤销、轮换和解绑后的存量连接不能继续读取或写入原 owner 数据；
- 恢复出厂清除网络和设备权限，并要求重新认领。

### EV-09 弱网恢复和会话重建

**学习点**：RTC 的价值主要在抗弱网、重连、抖动控制和实时信令，不只是换一个 SDK。

**交付物**：

- Wi-Fi、DNS、TLS、服务端和上游 provider 故障使用分层状态与退避；
- 重连建立新 session，不复用旧播放队列；
- 根据网络质量调整编码、缓冲或明确降级；
- 增加离线本地反馈，限制提示频率和重连风暴。

**验收**：

- 断网 30 秒恢复后可继续新对话；
- 断网期间录音和旧回复不补传、不补播；
- 高延迟、抖动、限速和压力丢包测试均有独立结果；
- 连接恢复不破坏 H5/设备最新连接优先规则。

### EV-10 设备状态反馈和可观测性

**学习点**：上游提供连接、智能体任务、字幕和会话阶段回调，可用于设备反馈和诊断。

**交付物**：

- 统一 provisioning、offline、connecting、listening、thinking、speaking、
  interrupted、error 状态；
- 将状态映射到 LED/提示音，但不把颜色当作唯一诊断证据；
- 上报 RSSI、重连次数、缓冲水位、欠载、堆内存、重启原因和版本；
- 诊断记录关联 base/session/turn，但不包含对话正文和密钥。

**验收**：

- 用户可区分没联网、服务未就绪、正在聆听、思考和播放；
- 现场问题可定位到设备、网络、ASR、LLM、TTS 或播放阶段；
- 遥测有频率和容量上限，离线时不形成无限积压；
- 日志脱敏检查通过。

- 列出供应商不可用时的回退方案。

- AK/SK/AppKey 只存在服务端；
- 设备只获得绑定 base、owner 和用途的短期房间令牌；

### EV-12 RTC Lite 媒体路径 PoC

**学习点**：验证 RTC 在真实 LINGOU 负载下是否比 WebSocket 路径更有价值。

**交付物**：

- 在 `spike/rtc-lite-transport` 中实现最小 RTC 会话；
- 服务端签发短期 room/token/task，并映射到现有 session/turn；
- 映射字幕、会话阶段、打断和 Function Call 回调；
- 不改现有 WebSocket 默认路径，不迁移共同记忆事实源。

**验收**：

- persona、最近历史和确认记忆与 WebSocket 路径一致；
- 取消、撤权、播放完成和最新连接仲裁语义不降低；
- PoC 可整体删除，不影响生产路径；
- 所有 RTC 资源和智能体任务在断开后按时释放。

### EV-13 WebSocket 与 RTC A/B 决策

**交付物**：

- 对比端点到首音频、打断、弱网恢复、带宽、音质、CPU、内存、功耗和成本；
- 分别测试稳定网络、抖动、限速、短断和长断；
- 记录 SDK 黑盒、许可证、芯片支持和运维复杂度；
- 给出保留 WebSocket、迁移 RTC 或双路径共存的结论。

**验收**：

- 决策门槛在跑测试前确定；
- 不使用上游宣传数字替代本项目测量；
- RTC 若没有形成足够的体验或可靠性收益，则维持现有路径；
- 通过评审后才允许把选定路径纳入正式硬件分支。

## 第四阶段：可选体验增强

### EV-14 LLM Prefill 和 TTS Burst

**学习点**：上游可用 ASR 中间结果预热 LLM，并为嵌入式设备快速发送一段 TTS 音频。

**交付物**：

- Prefill 只做推测计算，ASR final 前不提交日志、记忆或不可撤回副作用；
- TTS Burst 使用设备专属配置和有界缓冲，不与 H5/移动端共用；
- 对比首音频收益、额外模型费用、误识别浪费和内存占用。

**验收**：

- ASR 修正或用户打断时，推测结果可完整取消；
- 不产生重复回复、错误记忆或旧音频补播；
- 收益不足以覆盖成本和复杂度时保持关闭；
- 默认配置仍可回退到非 Prefill、非 Burst。

### EV-15 Function Calling、RAG 和视觉扩展

**学习点**：上游支持 Function Calling、知识库、联网检索和视觉输入。

**交付物**：

- 工具调用由服务端白名单执行，设备不直接执行模型生成的 GPIO 或系统命令；
- 每次调用携带 tool-call ID、owner、session、turn 和幂等键；
- RAG 与联网结果标明来源，不能覆盖用户已确认共同记忆；
- 视觉能力单独评估隐私、带宽、成本和硬件选型。

**验收**：

- 越权、重复、迟到和取消后的工具调用均被拒绝；
- 无硬件执行能力时返回结构化失败，不伪装成功；
- 这些能力默认关闭，不进入一期主路径；
- 每项产品能力单独立项和验收。

## 第五阶段：量产与最终验收

**交付物**：

- OTA 和恢复过程不泄露配置。

### EV-17 最终硬件综合放行
