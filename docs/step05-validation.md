# 第 05 步实施与验证报告

日期：2026-09-15。

结论：第 05 步“后端语音轮次”在本步约定范围内验证通过。
第 06 步未开始，等待用户单独批准。

## 范围

- 为每个语音连接建立稳定 `session_id`。
- 为每次识别完成后的回复建立独立 `turn_id` 和递增 `turn_sequence`。
- 定义同一底座的连接策略：`newest_connection_wins`。
- 统一打断、挂断、连接替换及新轮次开始时的取消行为。
- 阻止旧轮次的文本、音频、最终回复、状态和持久化结果污染新轮次。
- 记录识别完成到回复启动、首段文本、首段音频、完成或取消的关键时间。
- 不实施第 06 步的前端语音生命周期重构。

## 会话与轮次合同

同一底座只保留最新的已认证语音连接。新连接注册后：

1. 旧连接收到 `session_replaced`。
2. 旧连接活动轮次及其上游模型流被取消。
3. 旧连接以 `4410` 关闭。
4. 旧连接的 `finally` 不得移除新连接，也不得重置新连接状态。

服务端 JSON 消息统一包含 `session_id`。从 `final` 开始的轮次消息还包含
`turn_id` 和 `turn_sequence`。前端对 `session_replaced` 和 `4410` 做最小兼容，
明确退出旧通话且不自动抢回连接；其余前端生命周期优化仍属于第 06 步。

## 取消与迟到结果

每轮使用独立取消令牌。新一轮、barge-in、挂断或连接替换都会：

- 设置旧轮取消状态并取消其 asyncio task。
- 停止对应角色的本地播放队列。
- 拒绝旧轮后续文本和音频 WebSocket 写入。
- 主动关闭已经建立的模型 SSE 响应。
- 在最终持久化前再次检查取消状态。

取消令牌与最终提交使用同一同步锁：取消先发生则跳过写入；提交先完成则视为上一轮已经完成，
新轮只能在其后开始。角色状态与对话日志通过同一个 redo journal 事务提交，避免只更新其中一份。
语音对话日志保存对应 `session_id` 和 `turn_id`。

## 时间记录

每轮结束或取消时输出结构化 `VoiceTurnMetrics` 日志，并向当前客户端发送 `turn_metrics`：

- `speech_finalized_ms`
- `reply_started_ms`
- `first_text_ms`（实际成功发送时记录）
- `first_audio_ms`（实际成功发送时记录）
- `reply_completed_ms` 或 `cancelled_ms`

所有毫秒值以本轮识别文本稳定完成为零点；同时记录 UTC `started_at`。

第 05 步定向测试覆盖：

1. A/B 轮交错时，A 的迟到文本、音频和完整回复不能进入 B。
2. A 的结束清理不能把仍在执行的 B 标记为空闲。
3. 挂断会设置取消令牌，迟到输出被抑制。
4. 新连接替换旧连接，旧连接收到 `4410`，注册表仍指向新连接。
5. 完成轮消息携带一致的会话和轮次标识，并产出关键耗时。
6. 取消轮不更新角色状态、不写对话日志。
7. 完成轮把 `session_id/turn_id` 写入对话日志。
8. 取消会关闭正在读取的模型 SSE 响应。

测试只使用假 WebSocket、假模型生成器、假音频和临时数据目录。没有调用真实 ASR、LLM、TTS、
麦克风、扬声器或物理硬件。原项目运行数据未被测试读取或修改。

## 边界与下一步

- 上游模型在 TCP 连接尚未建立时无法被外部线程立即中断；连接建立后取消回调会关闭响应流。
- 当前会话注册表和取消协调是单进程实现，部署仍要求一个 worker。
- `turn_metrics` 已记录单轮关键点，但真实 P50/P95 和成本统计需要第 12 步用真实链路采样。
- 第 06 步将处理前端通话状态抽离、权限恢复、断线重连和跨页面资源释放；本报告不授予执行许可。
